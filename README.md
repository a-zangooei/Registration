## 🎯 معرفی و هدف سامانه

در دوره‌های علوم پایه پزشکی (ترم‌های ۳، ۴ و ۵)، به دلیل تعدد دروس دارای بخش‌های نظری و عملی (آزمایشگاه، کارآموزی و سالن تشریح) و برگزاری امتحانات میان‌ترم حذفی و پایان‌ترم متمرکز، انتخاب واحد سنتی همواره با چالش تداخل ساعات کلاسی و امتحانی و نقض پیش‌نیازها همراه است.

این سامانه به دانشجو اجازه می‌دهد با چند کلیک، وضعیت واحدهای اخذ شده را مدیریت نماید، تداخلات را به صورت بلادرنگ مشاهده کند، پیشنهادهای هوشمند برای گروه‌های عملی جایگزین دریافت کند و برنامه نهایی را به صورت **لینک اشتراک‌گذاری**، **فایل تقویم استاندارد (ICS)**، **PDF رسمی**، **فایل HTML مستقل** یا **تصویر باکیفیت (PNG)** ذخیره نماید.

---

## 🌟 ویژگی‌های کلیدی و قوانین آموزشی

### ۱. مدیریت هوشمند سقف و کف واحد
- **تنظیمات پیش‌فرض:**
  - کف مجاز انتخاب واحد: **۱۲ واحد**
  - سقف مجاز انتخاب واحد: **۲۰ واحد** (وضعیت عادی تحصیلی بر اساس آیین‌نامه رسمی دانشگاهی و دیتاست مصوب)
- **پیش‌تنظیم‌های تحصیلی سریع (Academic Ceiling Presets):**
  - **عادی (۲۰ واحد):** پیش‌فرض عمومی برای دانشجویان با معدل بالای ۱۲ تا ۱۷.
  - **معدل الف (۲۴ واحد):** برای دانشجویان ممتاز با معدل کتبی بالای ۱۷.
  - **مشروط (۱۴.۴۹ واحد):** سقف مجاز برای دانشجویان دارای شرایط مشروطی.
  - **تنظیم آزاد/دستی:** قابلیت درج هر عدد دلخواه برای کف و سقف توسط دانشجو.
- **محاسبه تفکیکی:** نمایش مجموع واحدهای نظری، عملی، پایه/تخصصی و عمومی به همراه درصد سهم هر دسته.
- **آینده‌نگری انتقال به ترم ۶:** محاسبه خودکار واحدهای باقی‌مانده از چارت درسی که به ترم ششم منتقل خواهند شد.

### ۲. بررسی پیش‌نیازها و هم‌نیازها
- دروس اخذنشده بر اساس دیتاست دوره و سوابق قبلی (`externalPassedCourses`) اعتبارسنجی می‌شوند.
- در صورت عدم رعایت پیش‌نیاز یا هم‌نیاز یک درس، هشدارهای تفکیک‌شده همراه با کد و نام درس وابسته صادر می‌شود.

### ۳. فیلتر جنسیتی دروس عمومی
- پشتیبانی از تفکیک گروه‌های برادران و خواهران در دروس عمومی معارف (مانند اندیشه اسلامی و دانش خانواده).

## 💡 موتور پیشنهاد هوشمند گروه‌های جایگزین (Conflict Resolver)

هنگامی که میان ساعات کلاس‌ها یا امتحانات تداخل رخ می‌دهد، دانشجو نیازی به آزمایش تصادفی تک‌تک گروه‌ها ندارد:
- سیستم به صورت خودکار تمام گروه‌های دیگر درس متداخل را ارزیابی می‌کند.
- گروه‌هایی که هیچ تداخلی با سایر دروس انتخابی کاربر نداشته باشند با برچسب سبز «بدون تداخل» شناسایی می‌شوند.
- گروه‌های دارای تداخل جدید شناسایی و به همراه جزئیات تعارض نمایش داده می‌شوند.
- کاربر می‌تواند با کلیک روی دکمه «اعمال این گروه»، گروه جایگزین را مستقیماً جایگزین کند.
- تداخل‌های غیرقابل حل کلاسی (مانند کلاس‌های تک‌گروهی نظری) یا تعارض تاریخ امتحان با ذکر دلیل مشخص به کاربر گزارش می‌شوند.

## 🔬 منطق گروه‌های عملی (شناور در برابر انتخابی)

دروس دارای بخش عملی (نظیر تشریح ادراری، فیزیولوژی، انگل‌شناسی، پاتولوژی و...):
1. **حالت بازه‌های شناور (Tentative Slots):**
   - پیش از انتخاب یک گروه قطعی، تمام بازه‌های گروه‌های ارائه‌شده با **استایل هاشورخورده (Hatched Pattern)** نمایش داده می‌شوند تا محدوده کلی اشغال ساعات مشخص باشد.
   - این بازه‌ها به عنوان تداخل قطعی شمرده نمی‌شوند تا کاربر فرصت تصمیم‌گیری داشته باشد.
2. **حالت تثبیت گروه انتخابی:**
   - پس از کلیک روی یک گروه خاص، سایر بازه‌های آزمایشی حذف شده و گروه برگزیده با **رنگ یکدست و قطعی** تثبیت می‌شود.

## ⚡ موتور تشخیص تداخلات سه‌گانه

سیستم مجهز به الگوریتم بررسی دقیق بازه‌های زمانی با تبدیل ارقام فارسی و تقویم شمسی است:
1. **تداخل ساعات کلاس:** بررسی همپوشانی بازه‌های `[StartA, EndA)` و `[StartB, EndB)` در یک روز هفته.
2. **تداخل امتحانات:** بررسی همزمانی امتحانات میان‌ترم و پایان‌ترم در یک تاریخ مشخص.
3. **بررسی بلادرنگ هاور (Hover):** با قرار گرفتن نشانگر ماوس روی هر درس، تداخل‌های فعال آن در جدول هفتگی با رنگ قرمز برجسته می‌شوند.

## 📊 ساختار و راهنمای دیتاست‌ها

دیتاست‌های برنامه با ساختار معتبر JSON ذخیره می‌شوند و تغییرات آن‌ها توسط آزمون‌های خودکار بررسی می‌شود.

### محل ذخیره فایل‌ها:
- `src/data/datasets/term-05-fall-1403.json`: نسخه باندل‌شده در زمان بیلد جهت دسترسی فوری بدون نیاز به Fetch اولیه.
- `public/datasets/manifest.json`: مانیفست اطلاعات دوره‌ها و نسخه‌ها (شامل شناسه، عنوان، سال تحصیلی، ترم، نسخه، وضعیت ممیزی و منبع).
- `public/datasets/term-05-fall-1403.json`: نسخه استاتیک و قابل دسترسی وب دوره جاری.
- `public/datasets/curriculum-template.json`: قالب نمونه استاندارد و معتبر برای ایجاد دوره‌ها یا ترم‌های جدید.

### نحوه افزودن یا اصلاح یک دوره آموزشی:
1. فایل `public/datasets/curriculum-template.json` را بررسی کرده و مقادیر مورد نظر را با ساختار داده زیر وارد نمایید:
   - فیلدهای الزامی ریشه: `id`, `title`, `academicYear`, `termNumber`, `minUnits`, `maxUnits`, `courses`
   - ساختار بازه‌های کلاسی (`theorySchedule` و `slots` در `practicalGroups`): شامل `day` (یکی از روزهای شنبه تا پنج‌شنبه)، `startTime` و `endTime` به فرمت معتبر `HH:MM`. زمان شروع باید اکیداً قبل از زمان پایان باشد.
   - تاریخ امتحانات (`midtermExam` و `finalExam`): باید به فرمت شمسی معتبر `YYYY/MM/DD` باشد.
2. مشخصات دوره جدید را به `public/datasets/manifest.json` اضافه کنید.
3. برای اطمینان از سلامت کامل ساختاری و معنایی، فرمان `npm test` را اجرا کنید. آزمون `curriculumValidation.test.ts` تمامی شروط را اعتبارسنجی می‌کند.

## 🌐 وضعیت واقعی قابلیت‌های آفلاین، PWA، اشتراک‌گذاری و خروجی

برای شفافیت فنی، وضعیت واقعی و محدودیت‌های هر ماژول به شرح زیر مستند شده است:

| قابلیت | وضعیت پیاده‌سازی | نیازمندی‌ها و محدودیت‌های واقعی |
| :--- | :--- | :--- |
| **PWA و کش Service Worker** | پیاده‌سازی کامل با `vite-plugin-pwa`، پیش‌کش خودکار فایل‌های استاتیک و آیکون‌ها | **محدودیت:** برای اولین بارگذاری (نصب اولیه) اینترنت الزامی است. پس از نصب، اجرای برنامه کاملاً آفلاین است. بررسی نسخه‌های جدید نیازمند آنلاین بودن است و با تست‌های خودکار در `pwaUpdate.test.ts` محافظت می‌شود. |
| **ذخیره‌سازی انتخاب‌ها** | ذخیره خودکار در `localStorage` مرورگر | انتخاب واحدها و برنامه‌های ذخیره‌شده حتی با بستن مرورگر یا حالت آفلاین حفظ می‌شوند. در صورت پاک‌سازی کش مرورگر، اطلاعات محلی پاک خواهد شد. |
| **اشتراک‌گذاری (URL Sharing)** | پیاده‌سازی با پارامترهای فشرده در URL (`courses`, `groups`, `g`) | کاربر با باز کردن لینک در هر دستگاهی مستقیماً همان چیدمان را مشاهده می‌کند. اشتراک از طریق تلگرام یا پیام‌رسان‌ها نیازمند اتصال شبکه است. |
| **خروجی تقویم (ICS)** | تولید استاندارد RFC 5545 برای امتحانات و کلاس‌ها | فایل `.ics` به صورت کلاینت‌ساید تولید شده و مستقیماً روی گوگل کلندر، اوت‌لوک یا اپل کلندر قابل ایمپورت است. |
| **پرینت و PDF رسمی** | استایل بهینه‌شده A4 افقی با `@media print` | از دستور بومی `window.print()` مرورگر استفاده می‌کند. در مرورگرهای موبایل خروجی ممکن است به تنظیمات مقیاس پرینتر مرورگر وابسته باشد. |
| **خروجی HTML مستقل و عکس PNG** | تولید در حافظه مرورگر بدون نیاز به سرور | فایل تک‌صفحه‌ای HTML بدون اینترنت باز می‌شود. عکس PNG با Canvas مرورگر ایجاد می‌گردد. |

## 💻 راهنمای نصب و اجرای محلی

### پیش‌نیازها:
- Node.js نسخه 20 یا بالاتر (`>=20.0.0`)
- npm نسخه 9 یا بالاتر

### مراحل اجرا:

```bash
# ۱. کلون کردن مخزن رسمی
git clone https://github.com/<your-username>/Registration.git
cd Registration

# ۲. نصب وابستگی‌ها
npm install

# یا در محیط‌های CI و بیلد تمیز منطبق با package-lock.json:
npm ci

# ۳. اجرای سرور توسعه محلی (Local Dev Server)
npm run dev

# ۴. اعتبارسنجی تایپ‌اسکریپت (Typecheck)
npm run lint

# ۵. اجرای تمامی آزمون‌های خودکار سامانه
npm test

# ۶. ساخت نسخه نهایی بهینه‌شده برای انتشار (Production Build)
npm run build

# ۷. پیش‌نمایش نسخه بیلدشده نهایی
npm run preview
```

پس از اجرای `npm run dev`، سامانه در آدرس `http://localhost:3000` در دسترس خواهد بود.

### 📱 راهنمای اجرا در محیط اندروید (Android ARM64 / Termux):
در صورت بروز نیاز به بسته‌های بومی Rust در Termux، اسکریپت آماده در نظر گرفته شده است:
```bash
npm run termux:setup
npm run dev
```

## 🚀 استقرار خودکار روی GitHub Pages

این پروژه یک وب‌اپلیکیشن کلاینت‌محور (SPA) بدون نیاز به بک‌اند یا دیتابیس است. پرونده گردش‌کار رسمی در مسیر `.github/workflows/deploy-pages.yml` قرار دارد و با تنظیم `base: './'` در `vite.config.ts`، سایت در هر زیرمسیر گیت‌هاب پیجز بدون مشکل لود می‌شود.

### مراحل فعال‌سازی در ریپازیتوری GitHub:
1. در مخزن گیت‌هاب به برگه **Settings** بروید.
2. از منوی سمت چپ گزینه **Pages** را انتخاب کنید.
3. در بخش **Build and deployment**، گزینه **Source** را روی **GitHub Actions** تنظیم کنید.
4. با هر دستور `git push` به شاخه `main` یا `master`، اکشن فعال شده، مراحل `npm ci`، `npm run lint` و `npm test` را اجرا می‌کند و در صورت موفقیت، خروجی پوشه `dist` را در نشانی زیر مستقر می‌سازد:
   `https://<username>.github.io/Registration/`
